Rootly

Manage incidents, alerts, and on-call with Rootly

Nutzungsanweisungen

Integrate Rootly incident management into workflows. Create and manage incidents, alerts, services, severities, and retrospectives.

Tools

rootly_create_incident

Create a new incident in Rootly with optional severity, services, and teams.

Eingabe

ParameterTypErforderlichBeschreibung
apiKeystringJaRootly API key
titlestringNeinThe title of the incident (auto-generated if not provided)
summarystringNeinA summary of the incident
severityIdstringNeinSeverity ID to attach to the incident
statusstringNeinIncident status (in_triage, started, detected, acknowledged, mitigated, resolved, closed, cancelled, scheduled, in_progress, completed)
kindstringNeinIncident kind (normal, normal_sub, test, test_sub, example, example_sub, backfilled, scheduled, scheduled_sub)
serviceIdsstringNeinComma-separated service IDs to attach
environmentIdsstringNeinComma-separated environment IDs to attach
groupIdsstringNeinComma-separated team/group IDs to attach
incidentTypeIdsstringNeinComma-separated incident type IDs to attach
functionalityIdsstringNeinComma-separated functionality IDs to attach
labelsstringNeinLabels as JSON object, e.g. {"platform":"osx","version":"1.29"}
privatebooleanNeinCreate as a private incident (cannot be undone)

Ausgabe

ParameterTypBeschreibung
incidentobjectThe created incident
↳ idstringUnique incident ID
↳ sequentialIdnumberSequential incident number
↳ titlestringIncident title
↳ slugstringIncident slug
↳ kindstringIncident kind
↳ summarystringIncident summary
↳ statusstringIncident status
↳ privatebooleanWhether the incident is private
↳ urlstringURL to the incident
↳ shortUrlstringShort URL to the incident
↳ severityNamestringSeverity name
↳ severityIdstringSeverity ID
↳ createdAtstringCreation date
↳ updatedAtstringLast update date
↳ startedAtstringStart date
↳ mitigatedAtstringMitigation date
↳ resolvedAtstringResolution date
↳ closedAtstringClosed date
